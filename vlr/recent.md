## 2. Latest Implementation
- **LOAD MORE TOURNAMENTS (pagination)**: `/events` is paginated (~50/page, 59 pages total). `_fetch_tournaments_page(page)` fetches `/events` (p1) or `/events/?page=N`; `_get_total_pages()` parses pagination. `get_tournaments(refresh=False, pages=N)` now returns a dict `{tournaments, fetched_at, error, total_pages, pages_fetched}` and fetches ONLY the missing pages (page 1 re-fetched only on refresh), merging into `tournaments_cache.json` (`pages`/`total_pages` keys; old-format cache learns total from p1 once). Sequential with 1s pause. Partial failure → returns what it has + error; no-op load-more retry does NOT reset the TTL. **Manual-only refresh (user preference)**: `TOURNAMENTS_CACHE_TTL` = ~1 year, so the cached `tournaments_cache.json` list effectively never auto-expires — it refreshes ONLY via the Refresh button in the Add Tournaments window. Refresh re-fetches exactly the pages the user currently has loaded (client sends `pages=pages_fetched` with `refresh=true`) — it must NOT request page 1 alone, or the cache would shrink back to 69 items. **Total pages self-updates**: `total_pages` is now parsed from EVERY fetched /events page (max), not just page 1, so if VLR.gg grows the list (e.g. 59 → 60 pages) the next "Load more" discovers it automatically; empty end-of-list pages no longer inflate `pages_fetched` (break happens before `highest_ok` is set). `/api/tournaments?pages=N` returns the new fields. UI: "Load more tournaments (page X of Y)" fetches +N pages per click — N = `tournament_pages_per_load` setting (default 5, editable in Settings > SCRAPE > "Tournament Browser", saved to settings.json via /api/settings; clamped 1-59). Hidden when all loaded; total_pages=1 = unknown → button stays. Status shows "X loaded (page A of B)", refresh icon spins; refresh + load-more buttons restyled as accent-red pills. Refresh has NO confirm popup (explicit action; spinner + status instead); tbr status texts cleaned up (no leading-space hack, padding moved to CSS). **Live refresh progress**: `get_tournaments` updates module-level `_refresh_progress` (active/total/done/current) per page when refresh=True; `/api/tournaments/progress` exposes it; client polls every 700ms during Refresh and shows "Refreshing — page X of Y…" + a red `.tbr-progress` bar (`.tbr-progress-fill` width = done/total). `app.run(threaded=True)` so the progress endpoint answers while a refresh runs. Tournament status chips color-coded via `mod-*` class on `.tbr-status`: ongoing=green, upcoming=blue, completed=grayed, paused=amber. **Add-tournament logo fix**: `add_tournament` stamps `tournament_logo` on all matches (from the /events list item `logo` field, sent by the client; falls back to `div.event-header img` on the event page), then `_upsert_matches_to_db` downloads it locally. Re-adding an already-added tournament backfills its logo (upsert updates the column). **Sync backfills missing logos**: `backfill_tournament_logos()` runs after every `/api/matches` sync — finds DB tournaments whose `tournament_logo` is empty, matches them against the cached /events list (`_loose_name_match`, exact-or-containment min len 8, longest-name wins), downloads + UPDATEs them in one transaction. `_bulk_upsert_rows` now protects `tournament_logo` (non-empty only) so a sync scrape with missing icons never wipes a stored logo. Note: backfill only sees tournaments present in the cached /events pages — older/defunct ones need a manual re-add to fetch logos.

Client: stats-loaded badges, `getMissingStatsMatches` and fully-loaded checks use `m.has_stats`; `matchHasPlayerStats` helper removed; `openLeaderboard` is async. **Shared cache**: `cachedAllMatches` (module-level in DOMContentLoaded scope) holds the `/api/matches/all` response for BOTH the leaderboard and the standings modal — fetched once per session instead of on every modal open (standings no longer force-refetches on each button click).
